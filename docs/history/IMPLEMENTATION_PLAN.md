# Implementation Plan

Decisions made from inspection (no blocking questions needed):
1. **Dataset:** none present -> Approach C, a clearly labelled synthetic dataset generated by `backend/scripts/make_synthetic_dataset.py`. The Kaggle PCA data is not used because the payment form cannot supply V1-V28.
2. **Database:** repository layer with two backends. `supabase` (production; forwards the user's JWT to PostgREST so RLS enforces ownership; no service-role key) and `sqlite` (local dev and automated tests, explicit `DB_BACKEND=sqlite`).
3. **Auth:** FastAPI verifies Supabase JWTs (HS256 secret `SUPABASE_JWT_SECRET`, or JWKS for asymmetric projects). Roles come from the verified token's `app_metadata.role` (set only by an admin), default `customer`; `analyst`/`admin` may review alerts.
4. **Frontend:** keep React/Vite + existing CSS; add reusable components, a test setup (vitest + Testing Library).

Order of work: backend ML -> backend API + auth + repositories -> migrations -> backend tests -> frontend components/pages -> frontend tests -> docs -> verification pass 1 -> pass 2.

Blockers expected: no live Supabase project, so live auth/RLS integration is BLOCKED; everything else is tested locally.
